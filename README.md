# ⚽ 足球速报 Football Daily Brief

> 每天 07:10 自动生成、自动发布的足球每日速报。**网页版 PWA + Flutter 安卓原生 App**，
> 支持全文检索与 AI 问答 —— 所有回答都强制标注来源日期，模型无权编造。

---

## 这个项目解决什么问题

足球新闻散在十几个站，每天自己刷一遍很费时间，而且**想查"上周发生了什么"时翻历史很痛苦**。

本项目把「每天抓取 → 结构化整理 → 自动发布」做成一条无人值守的流水线，并把历史数据沉淀成一个**可检索、可提问**的数据库。

---

## 两个形态

| 形态 | 位置 | 说明 |
|---|---|---|
| **网页版 PWA** | `足球速报/` | 深色卡片式速报，可离线缓存、可安装到手机桌面 |
| **Android App** | `足球速报_app/` | Flutter 原生 App（**非 WebView 套壳**），支持本地推送、App 内检查更新 |

App 每次启动异步拉取最新数据，具备**三层降级**：远端数据 → 本地缓存 → 内置数据，断网也不会白屏。

---

## 智能层：可搜索 + 可向 AI 提问（2026-10 新增）

这是本项目最核心的设计。**不把数据丢给模型让它"记住"，而是让模型只负责理解问题，答案永远从已发布的原文里查出来。**

```
用户提问 / 关键词
        │
        ▼
┌─────────────────────────────────────────────┐
│ ① 本地检索引擎（确定性代码 · 0 成本 · 可离线）  │
│    · 把 12 期速报摊平为 1043 个文档块           │
│    · 二元组(bigram)倒排索引 + BM25 打分         │
│    · 实体词典自动从语料抽取（球队/球员/联赛）      │
│    · 简称归一：巴萨→巴塞罗那，国米→国际米兰        │
│    · 相对时间解析：昨天 / 上周 / 最近 → 具体日期    │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ ② LLM 路由器（只做"理解"，输出结构化意图 JSON）  │
│    action: search | chat | reject            │
│    keywords / date_from / date_to / aspect   │
│    → 打招呼、超范围问题在本地直接处理，不浪费额度    │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ ③ 归纳层（只允许引用②查出的真实片段）           │
│    硬规则：只能使用给定材料 / 必须标注日期        │
│    材料里没有的 → 直接说"速报里没有相关记录"       │
└─────────────────────────────────────────────┘
        │
        ▼
   答案 + 依据原文（可点开逐条核对，跳到对应那一期）
```

### 为什么这么设计

| 常见做法 | 本项目做法 |
|---|---|
| 把全部数据塞给模型，靠它"记得" | 模型只理解问题，数据由**确定性代码**检索 |
| 模型可能编造内容，且不给来源 | 每条结论强制标注日期，可点开原文核对 |
| 每次提问都很贵 | 检索 0 token；打招呼/超范围问题 0 token |
| 没网/没额度就废了 | **搜索功能完全不依赖网络和 API**，纯本地 |

### 降级设计（任何一环挂掉都不白屏）

| 故障 | 表现 |
|---|---|
| 没配置 API key | 搜索照常可用；提问页给出配置引导 |
| 路由模型调用失败 | 自动把整句当关键词做本地检索 |
| 归纳模型调用失败 | 直接展示检索到的原文片段，并说明原因 |
| 模型输出被截断 | 明确报错并降级，不显示半截答案 |

## 配置 API Key（提问功能需要）

> ⚠️ **key 不写在代码里，也不会上传。** 站点是公开的，把 key 写进 JS 等于送给所有人。
> 设计上采用 **BYOK（自带密钥）**：每个用户在浏览器里填自己的 key，只存在 `localStorage`。

1. 打开站点的「问 AI」页
2. 点「去配置」，填入 API Key
3. 点「测试连接」确认可用

默认接入 **DeepSeek 官方 API**（`https://api.deepseek.com/v1`，模型 `deepseek-flash`），任何 OpenAI 格式兼容的接口都可以改地址接入。

> 注意：本项目使用的 `deepseek-flash` 是**推理模型**，思考过程会消耗 token，
> 因此 `max_tokens` 必须留足（路由器 1200、归纳 2400），给少了会返回空内容。

## 每日自动流水线

```
每天 07:10  定时任务抓取赛事素材
     │
     ▼  生成结构化日报（`足球速报-YYYY-MM-DD.md`）
     │
     ▼  add_report.py 解析 md → 合并进 report-data.js
     │
     ▼  自动发布站点（App 下次启动自动拿到新数据）
```

日常零人工维护。App 端通过站点上的 `update.json` 实现**应用内检查更新**。

## 本地运行

```bash
# 任意静态服务器都可以，例如：
cd 足球速报
python -m http.server 8000
# 打开 http://127.0.0.1:8000
```

> 不要直接双击 `index.html` 用 `file://` 打开 —— 浏览器会拦截跨域请求，AI 问答会失效（搜索仍然可用）。

### 自测脚本

```bash
# 检索引擎离线测试（14+ 用例：分词、别名、日期解析、板块排序、空结果边界）
node _work/smart-test.js

# AI 路由器端到端测试（真实调用，需要 key）
FB_KEY=sk-xxx node _work/ai-test.js
```

## 数据来源

内容来自公开赛事报道聚合，每条重点场次均附来源链接（见每期速报文末「来源」板块）。
本项目仅做信息聚合与结构化，**内容准确性以官方与原始报道为准**。

---

## 技术栈

**前端**：原生 JavaScript（无框架、无构建工具）、PWA、Service Worker
**检索**：bigram 倒排索引 + BM25 精简实现（零依赖，纯前端）
**AI**：DeepSeek Chat Completions API（OpenAI 兼容格式）
**App**：Flutter / Dart，Android 原生渲染
**自动化**：定时任务 + Python 数据合并脚本
